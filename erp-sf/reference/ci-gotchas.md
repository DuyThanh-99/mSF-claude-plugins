# CI gotchas

Known erp-salesforce CI failures, shared by `erp-sf:ci-fix` and `erp-sf:prd-to-feature`. Match the symptom before changing code. When a run teaches a new one, add a row (symptom as it appears in the log, cause, what to do, ticket or PR).

Read the failing job's log and its deploy report first. Deploy reports on dev-staging are read-only: `sf project deploy report -o staging --job-id <0Af…> --json`, run from `/private/tmp`.

| Symptom | Cause | What to do |
| --- | --- | --- |
| Every `tiered.pre_merge` job is skipped (`apex-test`, `check-coverage`, `create-package-version`, `backwards-compatible`, `sfdx-scanner`) | A label event started the workflow (e.g. the squad bot adding `payment-pr`), but the label is not `Ok to test` | Add the `Ok to test` label; nothing to fix in code |
| A component that the branch moved and then reverted is missing from the PR scratch org (e.g. `MANAERP:contactPhoto` not found) | CI deploys incrementally from the last fully successful deploy marker to HEAD; the move and the revert cancel out, so the component is never re-sent. Merging develop does not move the marker | Rebase the PR so the marker commit leaves its history; the next run deploys everything |
| `initialize-org` fails with `LWC1504` on a namespaced custom label | The script deploys LWCs that import labels the org does not have yet | Pass `--local-labels` (LT-113263 precedent); `scripts/start.bash` has the same calls for local `make start` |
| FlexiPage deploy fails: `Component [lst:dynamicRelatedList] attribute [adminFilters]: <Value> isn't a valid picklist value` | A packaged page filters on a record type that is not packaged (record types on packaged objects live in `outside-packages/access-control`) | Remove the record-type filter from the packaged page; show the content through a visibility rule instead (LT-114030) |
| Package install or upgrade fails because a removed component is still referenced | The release both stops using and deletes a component; Salesforce updates the package first, while the old references still exist | Two releases: restore the component (no new references) in this one, delete it in the next. LBAC/translation warnings on the restored components are expected |
| `validate-outside-packages-staging` fails with `In field: listViewButtons - no WebLink named …` or `no CustomField named …` | The job validates the outside post-install against dev-staging, which runs an older Main. `outside-package-post-install.bash` copies a `*__c.object-meta.xml` when its `git diff` matches `trackHistory\|sharingModel\|…`, and that grep also reads unchanged context lines | Expected until dev-staging gets a Main build with the change; real releases install Main first (LT-114803 merged with it). The script fix (grep only `^[+-]` lines) is a Platform change |
| `SharingGuestRule Contact.A: 選択リスト値は存在しません` | The guest rule matches the Student record type by its English label; the error comes back in Japanese when the shared CI user is in Japanese | Not from the branch; re-run the job |
| `Error (TypeInferenceError): Unexpected child metadata […User_Custom_Settings__c-ja/Allow_Soft_Delete_Contact__c…]` | CLI resolving the repo tree; the file has no parent object translation in `packages/order` | Noise next to the real error. Locally, deploy from a temp project holding only the changed files |
| `Sharing Violations Report` lists a class with `Missing "with sharing"` | Public class without a sharing keyword (test fixtures included) | Add `with sharing`; re-run the sharing scan locally |
| `permission-set-check` fails | New class, page, tab, record type, field or custom permission not granted in all 3 v2 sets | Add the grants with the `MANAERP__` prefix in `outside-packages-ext/access-control` |
